## 十四、许可证怎么选（创建仓库时用）

创建仓库时 GitHub 让你选 License（许可证），告诉别人"能怎么用你的内容"。下面是 GitHub 下拉框里的**全部选项**（按类型分好，共 35 种 + 无许可证）。

### 先懂三种类型（人话）

- **宽松型（Permissive）**：别人随便用、改、拿去商用，只要给你署个名。最常见是 MIT。
- **著佐权型（Copyleft）**：别人用了、改了，必须把改完的也开源。代表是 GPL。
- **内容型（Creative Commons，CC）**：专门给文字/图片/文档，不是给代码用的。

### 1）不授权

| 英文         | 中文   | 大白话                     |
| ---------- | ---- | ----------------------- |
| No license | 无许可证 | 版权全归你，别人不能乱用（只是能看，没授权用） |

### 2）宽松型（随便用，仅需署名）★新人重点看

| 英文 / 关键字                               | 中文             | 大白话                              |
| -------------------------------------- | -------------- | -------------------------------- |
| MIT（MIT）                               | MIT 许可证        | 最常用最简单：可看/用/改/商用，只需署名。**个人笔记首选** |
| BSD 2-Clause（BSD-2-Clause）             | BSD 两条款        | 和 MIT 几乎一样，极简                    |
| BSD 3-Clause（BSD-3-Clause）             | BSD 三条款        | 比 2 条多了"不能用我名字打广告"               |
| BSD 3-Clause-Clear（BSD-3-Clause-Clear） | BSD 三条款净化      | 给芯片/硬件用的变体                       |
| BSD 4-Clause（BSD-4-Clause）             | BSD 四条款        | 老版本，要求广告里致谢（现在很少用）               |
| 0BSD（0BSD）                             | BSD 零条款        | 比 MIT 还松：连署名都不用                  |
| Apache 2.0（Apache-2.0）                 | Apache 许可证     | 像 MIT，但多了"专利授权"条款，大项目常用          |
| ISC（ISC）                               | ISC 许可证        | 和 MIT 等价，文字更短                    |
| Zlib（Zlib）                             | zLib 许可证       | 很宽松，图形库常用                        |
| BSL-1.0（BSL-1.0）                       | Boost 软件许可证    | 很宽松，C++ 库常用                      |
| MS-PL（MS-PL）                           | 微软公共许可证        | 微软出的宽松许可                         |
| PostgreSQL（PostgreSQL）                 | PostgreSQL 许可证 | 像 MIT，数据库 PostgreSQL 用的          |
| NCSA（NCSA）                             | UIUC/NCSA 许可证  | 介于 MIT 和 BSD 之间                  |
| Unlicense（Unlicense）                   | 反许可证           | 直接放弃版权，爱用不用署名                    |
| WTFPL（WTFPL）                           | 想干啥干啥许可        | 玩笑式彻底放弃限制（名字不雅，正式少用）             |


### 3）著佐权型（Copyleft：改了必须也开源）

| 英文 / 关键字                   | 中文             | 大白话                       |
| -------------------------- | -------------- | ------------------------- |
| MPL-2.0（MPL-2.0）           | Mozilla 公共许可证  | 弱著佐权：只要求改过的"文件"开源，可混进专有项目 |
| EPL-1.0 / EPL-2.0          | Eclipse 公共许可证  | 给 Eclipse 项目用，含专利授权       |
| EUPL-1.1（EUPL-1.1）         | 欧盟公共许可证        | 欧盟政府项目用的著佐权               |
| OSL-3.0（OSL-3.0）           | 开放软件许可证        | 强著佐权                      |
| AFL-3.0（AFL-3.0）           | 学术自由许可证        | 偏著佐权，含专利条款                |
| GPL-2.0（GPL-2.0）           | GNU GPL v2     | 强著佐权：用了/改了必须全部开源          |
| GPL-3.0（GPL-3.0）           | GNU GPL v3     | 同上更新版，加了专利与硬件锁限制          |
| AGPL-3.0（AGPL-3.0）         | GNU Affero GPL | 最严：连"网上提供服务"也算分发，必须开源     |
| LGPL-2.1 / LGPL-3.0        | GNU 宽 LGPL     | 弱著佐权：常给"库"用，允许别人链接而不开源整体  |
| Artistic-2.0（Artistic-2.0） | 艺术许可证          | 主要给 Perl 用                |
| ECL-2.0（ECL-2.0）           | 教育社区许可证        | 教育机构用的弱著佐权                |

### 4）内容型（Creative Commons，给文字/图片/文档）

| 英文 / 关键字                   | 中文        | 大白话                          |
| -------------------------- | --------- | ---------------------------- |
| CC0-1.0（CC0）               | 公共领域奉献    | 放弃版权，别人随便用不用署名。**笔记想彻底公开可选** |
| CC-BY-4.0（CC-BY-4.0）       | 署名 4.0    | 别人可用/改，但必须署名                 |
| CC-BY-SA-4.0（CC-BY-SA-4.0） | 署名-相同方式共享 | 用/改必须署名，且衍生也要同许可             |
| CC（系列）                     | 知识共享系列    | 上面三种的统称                      |

### 5）字体 / 排版专用（小众，普通人用不到）

| 英文 / 关键字             | 中文            | 大白话        |
| -------------------- | ------------- | ---------- |
| OFL-1.1（OFL-1.1）     | SIL 开放字体许可    | 给字体文件用的    |
| LPPL-1.3c（LPPL-1.3c） | LaTeX 项目公共许可证 | 给 LaTeX 用的 |

### 我的建议（个人学习笔记）

- **首选 MIT**：最简单通用，愿意分享又保留署名。
- **想完全自己掌控** → No license。
- **想"谁爱用谁用、不署名"** → CC0 或 Unlicense。
- 笔记以文字为主，MIT 或 CC0 都合适；**别选 GPL / AGPL**（会逼着别人改了也得开源，对自己没好处）。

### 注意

- 选了以后**还能改**：删掉或替换仓库里的 LICENSE 文件即可。
- 公开仓库 + No license ≠ 别人不能看，只是没授权用。

| Stash                             | 储藏           | 临时把改动收起来，以后恢复            |
| Push                              | 推送           | 把你本地的提交传到 GitHub         |
| Pull                              | 拉取           | 把 GitHub 上的改动拿到本地        |

| Extensions                        | 扩展           | 装插件（装 Python、GitHub 的入口） |
| Settings（齿轮图标）                    | 设置           | VS Code 的设置              |
| Output / Problems                 | 输出 / 问题      | 看报错和提示的地方                |

**最常用的三个动作（每天都会点）：**

- 改完代码 → 在 Source Control 写一句说明 → 点 **Commit**
- 想存到 GitHub → 点 **Push**（或 **Sync** ↑↓）
- 想拿 GitHub 上的最新 → 点 **Pull**

## 十六、常见英文提示 / 报错（看不懂英文最慌，先记这页）

| 英文提示                                            | 中文意思            | 怎么办                              |
| ----------------------------------------------- | --------------- | -------------------------------- |
| Nothing to commit, working tree clean           | 没改动可提交，工作区是干净的  | 正常，说明你没改任何文件                     |
| Changes not staged for commit                   | 改动还没暂存          | 先 Stage（暂存）再 Commit              |
| Please enter a commit message                   | 请写提交说明          | 写一句这次改了啥，再确认                     |
| Permission denied (publickey)                   | 权限被拒（SSH 密钥没配对） | 改 HTTPS 方式，或配好 SSH 密钥            |
| Authentication failed                           | 认证失败            | 账号/密码(令牌)不对，重输                   |
| Support for password authentication was removed | 不再支持密码登录        | 改用 **Personal access token** 当密码 |
| fatal: not a git repository                     | 这不是 git 仓库      | 先 Clone 或 Init，别在错文件夹操作          |
| failed to push some refs                        | 推送失败            | 远端有你本地没有的改动，先 **Pull** 再 Push    |
| non-fast-forward                                | 非快进（同上的另一种说法）   | 先 Pull 合并远端改动                    |
| Merge conflict in 文件名                           | 某文件合并冲突         | 打开文件手动改掉 <<<<<<< 标记的部分           |
| CONFLICT                                        | 冲突              | 同上，需手动解决                         |
| Already up to date                              | 已经是最新           | 正常，本地和远端一致                       |
| remote: Repository not found                    | 找不到仓库           | 仓库名拼错，或你没权限                      |
| You've reached your pull rate limit             | 拉取次数超限          | 等一会儿再试（匿名拉取有限制）                  |

> 提示：从 2021 年起 GitHub **不再接受账号密码**登录 Git。VS Code 推送时要填的"密码"，其实是 **Personal access token（个人令牌）**，在 GitHub 网页 Settings → Developer settings → Personal access tokens 里生成。

## 二十、给你的上手建议（照着做就行）

1. 第一次进 GitHub，点右上角**头像 → Your repositories**，看你自己有哪些仓库。
2. 看别人项目，**先读 README.md**（说明文件），大半疑问它都写了。
3. 喜欢的项目点 **Star（收藏）**，不是 Fork——Fork 是你要改它代码才用。
4. VS Code 推送代码要填的"密码"是 **Personal access token**，不是你登录密码。
5. 在 VS Code 里每天就三件事：改完 **Commit** → **Push** 存云端 → 换设备先 **Pull** 拿最新。
6. 看不懂的英文，回来翻这张表对照，别硬猜。
7. 想手机 / iPad / 另一台电脑也能看，把这张表和你的笔记放进 GitHub 仓库（它本身就在云端）。
