# 学习笔记编写规范

> 保证笔记格式统一、好查找。写新笔记前瞄一眼。

## 1. 写什么
- 只写自己正在学的工具的操作步骤、中英对照、踩坑记录。
- 学什么写什么，不限定主题。
- 每篇都要有用、能复现，不写空话、不写无关内容。

## 2. 目录结构
- 按学习主题分文件夹，文件夹用中文：`github/`、`vscode/` ……
- 学一个新主题就新建一个文件夹，不强行归类。

## 3. 文件命名
- 中文 + `.md`，必要时带英文原词：`GitHub中英对照表.md`
- 不用空格，多词用 `-` 或 `_` 连接：`删除仓库步骤.md`
- 可带日期前缀：`2026-10-19-删除仓库.md`

## 4. 每篇笔记格式

```
# 标题（一句话说清主题）

> 一句话总结：这篇讲什么、解决什么问题。

## 正文
1. 分步骤写，带编号。
2. 看不懂的英文，记中英对照。
3. 报错必须写：原文 + 中文意思 + 怎么解决。

## 注意事项
- 容易踩的坑

## 日期与来源
- 创建：2026-10-19
- 来源：看书 / 看视频 / 自己实操
```

## 5. 英文处理
- 看不懂英文就记中英对照。
- 术语第一次出现写 `英文（中文）`，后面可只写中文。

## 6. 提交规范
- commit 信息用中文，写清改了什么：新增 / 修改 / 修正 + 说明。
- 例：`新增 GitHub 删除仓库步骤`

## 7. 跨设备
- 仓库在 GitHub 云端，任何设备登录都能用。
- 换设备先 Pull 再改，别两台同时改同一文件。

## 8. 写之前检查
- [ ] 放对文件夹？
- [ ] 文件名合规？
- [ ] 有步骤编号？
- [ ] 报错写了原文 + 中文 + 解法？
- [ ] README 索引更新了？
